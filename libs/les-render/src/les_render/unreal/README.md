## 1. One-time project setup

Use a **UE 5.4 or newer** project; 5.5 or 5.6 is recommended. Blank and Film/Video templates both work. In 5.3 the volume placement falls back to
index space; see [Placement knobs](#placement-knobs).

**Plugins** (Edit > Plugins, then restart the editor):

| plugin | why |
|---|---|
| Python Editor Script Plugin | runs `build_scene.py` / `render.py` |
| Editor Scripting Utilities | `EditorAssetLibrary`, used by older engines |
| Sequencer Scripting | Level Sequence Python API |
| Movie Render Queue (+ *Additional Render Passes*, optional) | rendering |
| Alembic Importer (includes Geometry Cache) | isosurfaces |
| Groom **and** Alembic Groom Importer | particle streaklines and trails as hair strands |
| Img Media (Media Framework) | slice PNG sequences |
| glTF Importer / Interchange (on by default in 5.x) | `geometry/*.glb`, slice planes |
| *(none needed)* Sparse Volume Textures and Heterogeneous Volumes | engine features since 5.3 (experimental) |

**Project settings:**

* *Rendering > Hardware Ray Tracing*: **Support Hardware Ray Tracing** and **Path Tracing** on. The Path Tracer needs these. On Windows use DX12 with SM6. On Linux use Vulkan SM6 on an RT-capable GPU (Linux path tracing is less battle-tested, so prefer Windows for final renders).
* *Rendering > Optimizations*: **Support Compute Skin Cache** on. Grooms need it.
* *Rendering > Heterogeneous Volumes*: **Shadow Casting** on if you want volumes to cast shadows in the deferred renderer (experimental).
* Optional: *Rendering > Default Settings > Motion Blur* on. MRQ temporal samples then give real motion blur.

## Coordinate frame and placement knobs

The bundle is in the simulation frame (metres, right-handed, z-up). Unreal
uses cm, left-handed, z-up: `(x, y, z)_m -> (100 x, -100 y, 100 z)_cm`.

| data | how it's placed | knob (top of `build_scene.py`) |
|---|---|---|
| `geometry/*.glb`, slice planes | Unreal's glTF importer converts y-up metres to cm. The script then compares the building bounds with `manifest.geometry.buildings_bounds` and auto-corrects a missing x100, a missing Y mirror or an x/y swap (logged as `buildings bounds check`). | `GEOMETRY_AUTOFIX` |
| Alembic (Blender exporter, y-up metres) | import conversion Rotation (90, 0, 0), Scale (100, -100, 100). This is Unreal's *Maya* preset times 100. | `ABC_ROTATION`, `ABC_SCALE` |
| VDB, UE 5.4+ | The SVT importer keeps the VDB grid transform, with 1 VDB unit = 1 cm and no axis change. The Heterogeneous Volume actor is placed at the origin with scale (100, -100, 100). | `VDB_PLACEMENT`, `VDB_AXIS_SIGN` |
| VDB, UE 5.3 | Index space: scale is 100 x voxel_size (Y negated), location is the manifest `origin` in cm | `LES_VDB_PLACEMENT=index` |

`auto` measures the volume actor's bounds at an identity transform and
picks `world` or `index` accordingly; the result is logged. **If the volume
appears mirrored**, change `VDB_AXIS_SIGN = (1.0, -1.0, 1.0)` to
`(1.0, 1.0, 1.0)`: this is the one-line fix. If it is offset, set the
placement explicitly. The contract is cell-centred: voxel (0, 0, 0)'s centre
sits at `origin`. In `index` mode the result can be off by half a voxel if
Unreal treats indices as cell corners.

Cameras: location is `sim_to_ue(location)`. Rotation aims at `target` with
`yaw = atan2(-dy, dx)` and `pitch = atan2(dz, |dxy|)`, with roll 0 (world +z up).
Yaw is unwrapped per shot. The filmback is 36 x 36·H/W mm, matching the
Blender preview's 36 mm horizontal fit. Focus distance is `|target - location|`,
the aperture comes from the key's `fstop`, and both are keyed per frame.

## Making it look great in Unreal

**Renderer.** The **Path Tracer** is Epic's documented cinematic path for
heterogeneous volumes. It needs `r.PathTracing.HeterogeneousVolumes 1`, which
the MRQ config sets. Epic describes heterogeneous-volume support in the path
tracer as "initial support", and Sky Atmosphere is not supported together
with it (the daylight look relies on the Sky Light's real-time capture).
Lumen/deferred rendering of heterogeneous volumes uses a separate ray
marcher tuned by *Step Factor* and *Shadow Step Factor* on the actor and the
`r.HeterogeneousVolumes.*` cvars. How well it interacts with Lumen GI is
**unverified**, so treat `--renderer lumen` as a quick preview path.

**MRQ settings** (set by `build_scene.py`, editable in the saved `MRQ_{{CASE}}` preset):

* Path Tracer: 1 spatial x 64 temporal samples with **Reference Motion Blur**.
  This is Epic's recommendation for animations: use temporal samples for
  noise and blur rather than spatial ones. Raise to 128–256 temporal samples
  for finals. Anti-aliasing override is *None*, since the path tracer
  accumulates its own samples. Engine warm-up is 16 frames.
* Lumen: 1 spatial x 8 temporal samples, 32 engine and 32 render warm-up frames (Lumen and TSR history).
* Console variables: `r.HeterogeneousVolumes.MaxTraceDistance 1e7`
  (large urban domains are otherwise clipped),
  `r.HeterogeneousVolumes.OrthoGrid.MaxBottomLevelMemoryInMegabytes 512` and
  `r.HeterogeneousVolumes.OrthoGridShadingRate 1` (Epic's cinematic values),
  `r.HairStrands.RaytracingProceduralSplits 2` (avoids BLAS build timeouts
  with grooms in the path tracer), and `r.HeterogeneousVolumes.IndirectLighting 1`
  (Lumen only).
* For stills or 4K, add the *High Resolution* setting (tiles). Use *Game Overrides > Cinematic quality* (already on).
* Output: 8-bit PNG, tone-mapped and sRGB, which is what ffmpeg and the HUD
  expect. Set `LES_OUTPUT_FORMAT=exr` for 16-bit linear EXR when grading.
  Pure-linear EXR additionally needs *Disable Tone Curve* on the pass.

**Look.**

* Exposure is **manual**: *Auto Exposure Method = Manual* with *Apply Physical
  Camera Exposure* off, so EV100 equals `exposure_bias`. Nothing pumps when
  the camera cuts.
* **Emissive + bloom** carries the dark look. Particles, volumes and
  isosurfaces are emissive, scaled by `emissive_gain`. Bloom is 1.2 (dark) or
  0.3 (daylight). In the path tracer, emissive surfaces also light the scene.
  Keep *Emissive Materials* on in the post-process path-tracing section.
* **Depth of field** comes from the CineCamera: f-stop keyed from the shots,
  manual focus at the target. Lower the `fstop` in `render.yaml` for a
  shallower look. Epic notes the path tracer renders DOF physically.
* **Motion blur**: post-process amount 0.4 (deferred), or MRQ temporal
  samples with Reference Motion Blur (path tracer).
* **Tonemapping**: Unreal's default Filmic tonemapper is ACES-based. For an
  ACES/OCIO pipeline use MRQ's *Color Output* / OCIO setting and EXR output.
* **AO**: set in the post-process volume (deferred only; the path tracer
  computes occlusion itself).
* **Buildings**: white clay (daylight) or dark matte with a faint Fresnel rim
  glow (dark). Parameters are exposed on `M_Buildings`.
* **Volumes**: all tuning lives on the `M_Volume_<layer>` parameters:
  `EmissionPerCm`, `ExtinctionPerCm`, `DensityScale`, `DensityMin/Max`
  (from `density_range`) and `ColorMin/Max` (from the LUT range).
  Emission and extinction are integrated per centimetre along the ray, so
  large domains need small values. Tune `EmissionPerCm` first.
* **Particles (groom)**: strands have no per-vertex speed in Unreal, so the
  material colours them along the strand with the layer LUT (`1 - U`,
  brightest at the head) and fades the tail (`TailFadePower`). Hidden points
  (`alpha == 0`) have width 0 in the groom cache. Visible widths are
  radius x (0.35 + 0.65 sqrt(alpha)), so the tail thins as well as fades. Blender
  writes the per-point *radius* into the Alembic widths, and whether Unreal reads
  that as a radius or a diameter is unverified. If strands look 2x too thin or
  thick, set the width override on the Groom asset (Strands group). Only
  position and width survive the export: no speed, alpha or `groom_color`.
  Size is about 16 B per point per frame. Blender's `--alembic-max-lines N`
  subsamples lines deterministically if the groom cache is too big.

## Layer notes and manual fallbacks

* **Volumes**: `.vdb` sequence imported as one animated Sparse Volume
  Texture. Only the first file is imported; Unreal detects the sequence from
  the numbered file names. The material uses a Volume domain with Additive
  blend and *Used with Heterogeneous Volumes*. It samples the SVT parameter
  `SparseVolumeTexture` at `(LocalPosition - LocalBounds.Min) /
  LocalBounds.FullExtents`, reads Attributes A.R, then applies the density
  window, the LUT via `luts/<layer>_lut.png`, emission and extinction. The
  actor's `Frame` is keyed with constant keys at every file change
  (`floor(frame / frame_step)`). *Fallback:* re-import the `.vdb` from the
  Content Browser. In the dialog, map grid `<layer>` to **Attributes A: R**
  (16-bit float), then assign the SVT to the `SparseVolumeTexture` parameter,
  or use Epic's template `/Engine/EngineMaterials/SparseVolumeMaterial`. If
  the volume does not animate, tick *Playing* on the actor and set *Frame
  Rate* = fps / frame_step.
* **VDB compatibility**: the bundle writes OpenVDB file format **224**
  (OpenVDB 11 or earlier) so that Unreal's bundled OpenVDB can read it. Files
  from OpenVDB 12 or newer are format 225, and older readers reject them with
  "unsupported VDB file format (expected version 224 or earlier, got version
  225)". The OpenVDB version bundled with each UE release (5.3–5.6) could not
  be confirmed from public sources, but every OpenVDB from 3.3 up reads 224.
  Unreal's importer also **rejects non-uniform voxels** ("OpenVDB importer
  cannot handle non uniform voxels"). `prepare_unreal` checks the file version
  and the voxel size and warns about both. There are forum reports of VDB
  imports that worked in 5.4 failing in 5.6.1/5.7, with no known cause. If the
  importer fails, try importing one file by hand to see the dialog's error.
* **Particles**: `alembic/<layer>.abc` curves are imported as a **Groom
  asset + Groom Cache** (Hair Strands factory, conversion rotation 90/0/0 and
  scale 100/-100/100). A Groom Actor carries a Groom Cache track. If no Groom
  Cache appears (automated groom-cache import is unverified), re-import the
  `.abc` by hand, tick *Import Groom Cache*, and add a *Groom Cache* track on
  the actor. If groom import fails entirely, the stage logs those same manual
  steps and skips the layer -- there is no Geometry Cache fallback (nothing in
  the bundle pipeline writes a `<layer>_mesh.abc` for one to import).
* **Isosurfaces**: `alembic/<layer>.abc` becomes a **Geometry Cache**
  (varying topology is fine) with a Geometry Cache track. Blender writes the
  colour as a per-corner C4f param `Cd` holding **sRGB-encoded** floats (PLY
  bytes / 255). The material decodes it with `pow(Cd, VertexColorGamma)`,
  default 2.2 (`VERTEX_COLOR_GAMMA` knob). If the colours look too dark, the
  importer already decoded sRGB: set the parameter to 1. If no colour arrives
  at all, set `UseVertexColor` to 0 and pick `FallbackColor`.
* **Slices**: an *Img Media Source* on `slices/<layer>/` (frame-rate override
  fps / frame_step) feeds a *Media Texture*, shown on a two-sided Unlit
  Translucent plane. Opacity comes from the PNG alpha, which is 0 inside
  buildings. A master *Media* track plays it in sync. If the material reports
  a sampler-type error, open it and set the texture node's sampler to *Color*
  (or *External*). For frame-exact media in MRQ, keep engine warm-up frames
  above 0.
* **HUD**: not handled in Unreal. See section 4.

**Unverified. Behaviour or names that could not be checked without Unreal:**

1. **SVT automated import.** Whether `AssetImportTask(automated=True)` on a `.vdb` skips the
   import dialog, detects the sequence, and maps the single float grid to Attributes A.R.
   `SparseVolumeTextureFactory` exposes no options object.
2. **SVT transform.** That UE 5.4+ applies the VDB transform with 1 VDB unit = 1 cm and no axis
   conversion. This is inferred from the docs ("supports transforms with scaling, rotation,
   translation") and community Houdini recipes (rotation 90/0/0 plus scale 1/-1/1 for y-up
   VDBs, and "scale by 100"). `auto` placement plus the logged bounds are the safety net.
3. **Material pin names.** Names used with `connect_material_expressions`:
   SVT sample input `UVs` / output `Attributes A`; ObjectLocalBounds outputs `Min`,
   `Full Extents`; HairAttributes output `U`; Power inputs `Base` / `Exp`. The script tries
   several spellings and warns if none connects.
4. **Volume-domain Extinction.** That Extinction is `MP_SUBSURFACE_COLOR` (it is labelled
   "Extinction" in the Volume domain), and that heterogeneous-volume emission and extinction
   integrate per cm.
5. **HV Frame keying.** That `HeterogeneousVolumeComponent.Frame` is keyable as a float
   property track, and that an SVT *parameter* on the material is what the component
   animates.
6. **Groom import.** That the automated Hair Strands import also creates the Groom Cache
   (the defaults of `GroomCacheImportSettings` are not documented). Also that
   `GroomComponent.set_material(0, ...)` overrides the groom's material slot.
7. **Alembic vertex colours.** That the Alembic importer maps Blender's
   face-varying C4f `Cd` param to geometry-cache vertex colours, and whether it
   decodes sRGB itself (see `VERTEX_COLOR_GAMMA`). Also whether groom widths
   are read as radius or diameter.
8. **glTF axis mapping.** The exact axis mapping of Unreal's glTF importer. The
   bounds-based auto-fix covers the x100, Y-mirror and x/y-swap cases.
9. **Media textures.** The Media Texture sampler type in the slice material (Color vs
   External), and Img Media frame accuracy under MRQ.
10. **Enum spellings.** Some enum members render with a trailing underscore in the docs
    (`MovieSceneKeyInterpolation.LINEAR_`). `_enum()` accepts both spellings.
11. **Commandlet support.** Level creation and the MRQ queue subsystem inside the
    `-run=pythonscript` commandlet. `-ExecutePythonScript` (full editor) is the
    recommended path.
12. **Component bindings.** That `add_possessable(component)` for the CineCamera and volume

13. **Bundled OpenVDB version.** Which OpenVDB each UE release bundles, so
    format-224 readability is inferred rather than confirmed.
14. **Path tracer and Lumen.** Grooms in the path tracer (documented "experimental",

## Troubleshooting

* **Nothing visible in the volume.** Check the Output Log for `volume <name>:
  placement=...`. Try `LES_VDB_PLACEMENT=index`, then raise `EmissionPerCm`.
  Confirm the SVT has Attributes A.R populated (open the asset).
* **Volume invisible beyond a distance.** Check `r.HeterogeneousVolumes.MaxTraceDistance`.
* **Everything mirrored.** Check the `buildings bounds check` log line. Then
  check `ABC_SCALE` (Y sign) and `VDB_AXIS_SIGN`.
* **Grooms render black or not at all.** Turn on *Support Compute Skin Cache*,
  confirm the material is a Hair shading model with *Used with Hair Strands*,
  and add engine warm-up frames.
* **Render is noisy.** Raise temporal samples. With the path tracer, also
  enable a denoiser (post-process *Path Tracing > Denoiser*, the NNE/OIDN plugins).
