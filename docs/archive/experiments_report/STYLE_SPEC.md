# Unified presentation spec for experiments_report (READ FULLY BEFORE EDITING)

Goal: sections 2–4 (esmda, filtering, filter_smoothing) must read as if written by one
author with one template; section 5 (comparison) reuses the same IDs, terms and crops.

## 1. Run IDs (fixed; use everywhere — text, tables, captions)
IDs are assigned by sorting run-directory names alphabetically within each campaign and
numbering from 1: ESMDA `E1..E20`, filtering `F1..F21`, filter smoothing `H1..H20`
(H = hybrid). Generate the mapping in the extract script (sorted(os.listdir) excluding
`_logs`, `_scratch`, `.DS_Store`) and emit an **experiment-matrix table** as the first
table of the section: columns `ID | truth | case | loc | <method knob(s)> | status`
(status = ok / failed (truth run)). Failed runs keep their ID. The folder name is given
ONLY in this matrix table (in \code{}); everywhere else use the ID, optionally followed
by a short descriptor, e.g. "E6 (uDALES, inflow_turb, loc, obs15)".
NOTE: filtering currently uses F-numbers already; re-derive them from the sorted rule
and check they match — if not, renumber consistently.

## 2. Section skeleton (identical order and titles in all three method sections)
\section{<Method name>}                       % ESMDA / Sequential filtering (EnKF) / Filter smoothing (hybrid)
\subsection{Method and experiment matrix}    % ≤ 1 page: what is specific to this method
                                             % (algorithm, knobs swept), then the matrix table.
                                             % Do NOT repeat the shared setup from Section 1.
\subsection{Master results}                  % master table + 3–6 sentence reading guide
\subsection{Results by case}                 % uDALES truth only
  \subsubsection{Laminar inflow (\code{inflow})}
  \subsubsection{Turbulent inflow (\code{inflow\_turb})}
  \subsubsection{Periodic boundaries (\code{periodic})}
     Each subsubsection: exactly this figure set, in this order, then the findings:
       (a) fig: validation sensors — sensor 0 + sensor 3 (elevated) + error panel
           (the "Fig-43 crop"), for the reference run of the case
       (b) fig: parameter error timeseries (α and |U| panels) for the reference run
       (c) fig: final-knot prior/posterior marginals (α and |U|) for the reference run
     Reference run of a case = uDALES truth, loccorrelation, obs15 / joint+RTPS.
     Findings as a short bulleted list: state, parameters, calibration (3–6 bullets).
\subsection{Model error (PALM truth)}        % one fig: validation sensors PALM vs uDALES for inflow_turb; bullets
\subsection{Sensitivities}
  \subsubsection{Localization}               % paired comparison table or fig; bullets
  \subsubsection{<Method knob>}              % ESMDA: observation interval; filtering: inflation/mode ladder;
                                             % filter smoothing: ESMDA aggregation interval (with caveat)
\subsection{Calibration}                     % calibration table + rank-histogram fig (3 cases in one row)
\subsection{Failed runs and cost}            % short; cost table may be folded into matrix or master table
\subsection{Takeaways}                       % ≤ 7 bullets, each starting with a bold 2–4-word claim
Optional at the very end: \subsection{Appendix: all runs} with the parameter-error grid.
Do not add other subsections. Keep each method section to ≈ 12–16 pages.

## 3. Tables (same schema in every method section; generated by scripts/extract_*.py)
Master table columns, in this order (use "—" if a metric does not exist for the method):
  ID | case | loc | knob | assim RMSE | valid RMSE | field |U| RMSE | α RMSE [deg] (red %) | |U| RMSE [m/s] (red %) | χ² | z_par | q | wall [h]
  - assim/valid = sensor **vector** RMSE mean over time (run_summary sensor_metrics.*.velocity_vector_rmse.mean)
  - field |U| RMSE = state_metrics.vel_magnitude_rmse.mean
  - α / |U| = parameter_metrics.<p>.rmse.mean; red % = 100*rmse_reduction_vs_prior; for
    state-only filters print the α/|U| value in italics with † and no red% (carried prior)
  - χ² = mean innovation chi2 from cycle_diagnostics (filters/hybrid); ESMDA: —
  - z_par = parameter_metrics.pooled.z_score.std; q = field_metrics.hit_rate_posterior.q (— if absent)
  - wall = timing total seconds / 3600
  - group rows: uDALES truth block first, then PALM truth block, \midrule between; failed runs as a
    single row with "failed (truth run)" spanning the numeric columns
  - bold = best per column within each truth block (lower is better; for q closest to… no: do not bold q or χ²)
Calibration table columns:
  ID | case | loc | knob | χ² | z_α | z_|U| | z_pool | contraction α | contraction |U| | q | q_u | q_v | q_w | rank edge frac (valid)
Both tables: \footnotesize, \begin{adjustbox}{max width=\textwidth}, booktabs, 3 significant
digits (RMSE 3 decimals, angles 2 decimals, red% integer), caption starts with "<Method>: ..."
Use macro names \<Method>MatrixTable, \<Method>MasterTable, \<Method>CalibTable with
Method ∈ {Esmda, Filt, Hyb}. Put ALL tables in sections/<method>_tables.tex.

## 4. Figures (shared crop library: scripts/figlib.py — create/extend, all section scripts import it)
figlib must provide, working on the raw run PNGs (same layout in all three campaigns):
  crop_validation(run_dir, sensors=(0,3), with_error=True, title=...)  -> PIL image: sensor 0 panel,
       sensor 3 panel, sensor-error panel stacked (the layout of figures/comparison/cmp_valid_timeseries.png)
  crop_param_error(run_dir, title=...) -> α panel + |U| panel stacked (from parameter_error.png)
  crop_marginals(run_dir, title=...)   -> final-knot α and |U| violins side by side (from parameter_marginals.png)
  crop_rank_hist(run_dir, title=...)
  hstack(images, labels)/vstack(images, labels) with a bold label strip (same font/size everywhere)
  save(img, path, max_width=1600)
Figure conventions:
  - width=\textwidth for stacked/multi-panel figures; ≤1600 px; PNG
  - label strips use "ID · case · knob" e.g. "E6 · inflow_turb · loc, obs15"
  - captions: first sentence names the run ID(s) and what is shown; then one sentence of reading guide
  - figure file names: figures/<method>/<type>_<ID>.png or <type>_<caseset>.png
  - IMPORTANT axis caveat: filter-smoothing sensor/parameter figures have the x-axis in cycle index
    (0–180, 2 s per cycle) whereas ESMDA/filtering figures use seconds (0–360). Say so in captions
    whenever the two appear together; do not try to redraw.
  - ~10–14 figures per method section, one figure per (a)/(b)/(c) slot per case (may combine the 3 cases
    of one type into one figure with hstack if it stays legible).

## 5. Terminology and notation (use exactly these)
  inflow angle α, velocity magnitude |U| (\Umag); "assimilated sensors"/"assim" and "validation
  sensors"/"valid"; "field |U| RMSE"; "vector RMSE" for sensor metrics; "reduction vs prior";
  cases: laminar inflow (\code{inflow}), turbulent inflow (\code{inflow\_turb}), periodic
  (\code{periodic}); "uDALES truth" / "PALM truth" (model error); "localization on/off"
  (\code{loccorrelation}/\code{locnone}); ESMDA-only = E, joint EnKF = F (joint), state-only
  EnKF = F (state, none/RTPS), hybrid = H. Method names in comparison figures: "ESMDA",
  "EnKF state+RTPS", "EnKF joint+RTPS", "Filter smoothing".
  Colour words: \good{} for clearly positive, \bad{} for clearly negative; use sparingly.
  Numbers: quote at most 3 significant digits in prose. Never quote reduction-vs-prior across modes.
